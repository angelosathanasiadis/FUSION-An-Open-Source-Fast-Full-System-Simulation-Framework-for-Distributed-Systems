# FUSION OMNeT++ WORKSPACE

The FUSION OMNeT++ WORKSPACE implements a modular simulation environment designed to seamlessly integrate with QEMU instances (such as x86 and RISC-V nodes). In addition, it contains all modifications required to extend the functionality of the OMNeT++ network simulator to work with the FUSION framework, utilizing the INET framework for realistic network modeling.

## Introduction
The key idea behind using a dedicated network simulator in FUSION is to support multiple network protocols, topologies, and complex congestion scenarios through which full-system nodes (represented by QEMU instances) can be interconnected. OMNeT++ was selected as the most widely used network simulator for this purpose. 

FUSION ensures seamless integration by utilizing specialized modules that bridge QEMU and OMNeT++. Raw Ethernet frames generated by the simulated software inside QEMU are encapsulated at the simulated-host boundary, traverse the configured INET links (switches, queues, routing components), and are accurately decapsulated and returned to QEMU upon reaching their destination. The guest's own transport implementation therefore observes the packet timing and loss behavior produced by the simulated network.

## HLA Enabled Node Functionality
QEMU instances are connected to OMNeT++ through the High-Level Architecture (HLA) standard using the open-source cCERTI RTI. For each QEMU instance, a corresponding node is created within OMNeT++, called an HLA-Enabled node. 

These nodes transparently communicate with QEMU, encapsulating and decapsulating network packets while maintaining an externally coordinated logical clock. Within OMNeT++, these HLA-Enabled nodes can communicate with any normal INET node (e.g., routers or switches), allowing support for arbitrary, multi-node network topologies. This structure allows networks to be generated and configured completely independently of QEMU.

## What is contained in the FUSION OMNeT++ WORKSPACE?

- `INET Framework`: Used by FUSION to model real network infrastructure (switches, queues, protocols).
- `HLANode`: The core FUSION project that interconnects OMNeT++ with QEMU instances through the cCERTI HLA wrapper.
- `FUSION_Demos`: Projects containing base topologies and test scenarios connecting multiple QEMU simulated nodes.

For more details on the overall architecture, please refer to the main [FUSION Framework](https://github.com/angelosathanasiadis/FUSION-An-Open-Source-Fast-Full-System-Simulation-Framework-for-Distributed-Systems) repository.

## Building the FUSION OMNeT++ WORKSPACE
*(Assuming the OMNeT++ IDE is installed and correctly configured)*

1. Navigate to `Project -> Clean...`
2. Select **Clean Projects Selected Below**.
3. Select `INET`.
4. Ensure **Start a build immediately** and **Build only the selected projects** are checked.
5. Press **OK** and wait for the INET compilation to finish.
6. Repeat the process (Steps 1-5), but this time select `HLANode` and your active simulation/demo project.
